Windows 11 Jump Lists missing or not working

Why Jump Lists show nothing for some apps and disappear entirely on others, how the recent items setting affects them, and how to get one working recents list on your taskbar.

On this page

  • What a Jump List actually is
  • Why one app has none
  • Why every app lost them
  • Getting them back
  • One working list instead of per-app ones

What a Jump List actually is

A Jump List is the list Windows shows when you right-click a taskbar icon: recent documents for that app, plus pinned items you chose to add. It is stored per application, in a file under %AppData%\Microsoft\Windows\Recent\AutomaticDestinations.

Two separate things can go wrong, and they have different causes. Knowing which one you have saves a lot of guessing.

Why one app has no recent files

If most apps show Jump Lists but one specific app never does, that app simply does not write them. Portable apps, games, some older desktop software, and most command-line tools never record recent documents.

No setting fixes this, because there is nothing recorded to display. Check whether the app writes any recent-file entries at all by looking at its own recent list inside the application. If the app does not track recent files internally, Windows has nothing to show either.

Why every app lost them

If no app shows recent files, the cause is system-wide. Two candidates:

  • The Start setting is off. "Show recently opened items in Start, Jump Lists, and File Explorer" governs recording for all three at once.
  • A policy is overriding it. The same setting can be forced off by group policy, and the local toggle will appear to do nothing.

Files opened while recording was off are not recoverable. The list only contains what was written at the time.

Getting them back

Toggle the setting off, wait a moment, toggle it on again, then restart. Restarting matters, because shell components cache the old value and keep the stale state until they reload.

Stop-Process -Name explorer -Force

If that does not help, check for a policy:

reg query "HKLM\SOFTWARE\Policies\Microsoft\Windows\Explorer" /v NoRecentDocsHistory

If the AutomaticDestinations folders are damaged, clearing them forces Windows to rebuild them. The next few files you open will repopulate the list.

A corrupt list is rare

If Jump Lists work for some apps and not others, resist clearing everything. You lose the history for the apps that were working, and rebuild nothing that was already fine. Diagnose per app first.

One working list instead of per-app ones

Jump Lists are per-app by design, which is useful when you work in one program and awkward when you do not. To find the file you need, you have to guess which app opened it, then check that app's list.

FanFolder collects recent documents from all Jump Lists plus Explorer's recent files into a single fan on the taskbar. One click shows everything you have touched recently, across every app, newest first. When an individual Jump List is empty or broken, the combined list still finds the file.

It reads what Windows already stored. It does not patch the shell, so it is unaffected by the recording setting and by the toolbars removal described in the Quick Launch guide.

winget install OleBhartvigsen.FanFolder

Common questions

What is the difference between Jump Lists and Recent files?

Jump Lists are per-app and appear when you right-click a taskbar icon. Explorer's Recent folder is one combined list of everything opened. FanFolder shows the combined view on the taskbar.

Can I recover Jump List entries from before recording was turned off?

No. Entries are written as you open files, so anything opened while recording was off was never stored. The list only rebuilds forward from when it was re-enabled.

Does clearing AutomaticDestinations affect installed apps?

No. Those folders hold only recent-item metadata and pinned Jump List entries, not program files. Clearing them resets history and pinned items, nothing else.

Will a Windows update break FanFolder?

It is an ordinary application, not a shell patch. It reads documented recent-file data. A Windows update cannot break it the way it can break ExplorerPatcher or StartAllBack.
